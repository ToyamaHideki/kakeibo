---

## 1. 目的

カテゴリ管理モーダル（`CategoryAddModal`）は現状、**追加・削除のみ**サポートで、既存カテゴリの**名前・色・費目種別を変更する手段がない**。

色や名前を変えたいユーザーは「削除 → 新規追加」を強いられ、その場合：
- カテゴリ ID が変わるため、過去の取引データとの紐付けが切れる
- 並び順や予算設定が失われる

そこで「既存カテゴリの修正機能」を追加し、ID を保ったまま属性を編集可能にする。
世帯カテゴリ・個人カテゴリの両方を対象とする（コンポーネントを共通利用しているため一度の改修で両対応）。

---

## 2. スコープ

| 機能 | 内容 | 適用 |
|---|---|---|
| 修正ボタン | 各カテゴリ行に鉛筆アイコン追加 | 世帯・個人 |
| 編集モード | 押下でフォームに既存値ロード | 世帯・個人 |
| 更新保存 | `updateCategory` / `updatePersonalCategory` 呼び出し | 世帯・個人 |
| キャンセル | 編集モード解除（新規追加モードへ戻る） | 世帯・個人 |
| 編集中表示 | 編集中のカテゴリ行を視覚的に強調 | 世帯・個人 |

非対象：
- 表示順（order）の編集（予算画面の並べ替えで対応済み）
- タイプ（収入/支出）の変更（取引データ整合性のため不可）

## 4. データフロー

### 4.1 編集モード開始
```
ユーザー：修正アイコン押下
   │
   ├─ setEditingId(cat.id)
   ├─ setName(cat.name)
   ├─ setColor(cat.color)
   └─ setExpenseType(cat.expenseType ?? 'variable')
```

### 4.2 編集保存
```
「更新する」押下
   │
   ├─ updateCategoryFn(editingId, { name, color, expenseType? })
   │     └→ Firestore 更新（世帯 or 個人）
   ├─ onUpdated(更新後 Category)
   │     └→ useCategories.updateCategoryLocally でローカル state 更新
   └─ 編集モード解除 → 新規追加モードに戻る
```

### 4.3 編集モード解除
```
「✕ キャンセル」押下
   │
   └─ editingId = null、フォームをデフォルト値にリセット
```

## 5. データ構造

### 5.1 既存関数の再利用

| 範囲 | 関数 | 場所 |
|---|---|---|
| 世帯 | `updateCategory(householdId, id, data)` | `src/firebase/firestore.ts:37` |
| 個人 | `updatePersonalCategory(uid, id, data)` | `src/firebase/personalFirestore.ts:26` |

→ **新規 Firestore 関数は不要**。既存関数を Props 経由で渡す。

### 5.2 ローカル state 同期パターン

- `useCategories`：`updateCategoryLocally(category)` を追加（tanstack-query の `setQueryData`）
- `usePersonalCategories`：`updateCategoryLocally(category)` を追加（`setCategories(prev)`）
- いずれも既存の `addCategoryLocally` / `removeCategoryLocally` と同パターン

### 5.3 Firestore スキーマ

変更なし。既存の `categories/{id}` ドキュメントへの属性更新のみ。

### 5.4 Firestore Rules

変更不要（既存 update rule の範囲内）。

## 6. 表示条件・分岐

| 状況 | 振る舞い |
|---|---|
| 編集中に別カテゴリの「修正」を押下 | ターゲット切替（フォーム値も切り替わる） |
| 編集中に「削除」アイコン押下（編集対象自身） | 削除確認 → 削除 → 編集モード自動解除 |
| 編集中に「削除」アイコン押下（他カテゴリ） | 削除のみ実行、編集モードは継続 |
| 編集中に名前を空欄にして送信 | 既存と同じく送信無効化（disabled） |
| 編集中にモーダルを閉じる | 編集 state ごとリセット |
| ゲストモード | `updateCategory` の guest 分岐が既存対応 → そのまま動作 |
| 収入カテゴリの編集 | 費目種別 UI は非表示（type=expense のみ表示）。既存仕様継承 |

## 7. 非機能要件

### 7.1 パフォーマンス
- 編集は単一ドキュメント update → I/O 1 回
- ローカル state 即時反映（楽観的更新と同等）

### 7.2 アクセシビリティ
- 修正ボタン：`title="修正"` / `aria-label="修正"`
- 編集モード時のフォーム見出し変化で文脈を明示

### 7.3 デザイン一貫性
- 鉛筆アイコンは TransactionList の編集ボタン（`SVG path d="M11 4H4..." / "M18.5 2.5..."`）と同型のシンプル線画
- 編集中の行は背景 `bg-sage-50` 系 or 左にアクセントバーで強調

### 7.4 既存挙動の保護
- 新規追加・削除・色プリセット・カスタムカラー・モーダル閉じる挙動は完全に維持
- 既存テスト（特に TransactionModal.test.tsx 周り）の regression なし

## 8. 既知リスク・考慮事項

| リスク | 対応 |
|---|---|
| 編集中に同じカテゴリを削除→クラッシュ | 削除実行時に editingId === id なら自動的に編集モード解除 |
| 編集中に props.categories が外部で更新されカテゴリが消える | フォーム入力中の値は維持。次回送信時に updateCategoryFn が失敗→エラーハンドリング |
| ゲストモードでの更新 | 既存 `updateCategory` の guest 分岐が `guestUpdateCategory` を呼ぶため対応済み |
| Layout.tsx の OutletContext 変更による既存ページの破壊 | optional 追加にする（既存ページが OutletContext を destructure する箇所は影響なし） |
