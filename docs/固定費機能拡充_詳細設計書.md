## 0. 実装担当者への注意（必読）

1. **固定費(FixedCost)の構造・既存挙動は変えない**。本機能は「契約(Contract)を固定費一覧に参照表示する」ための**集約レイヤ追加**が主。
2. 契約のカレンダー位置は **`renewalDate` の日/月から導出**。`renewalDate` 未設定の契約は固定費一覧に**出さない**（除外）。
3. 契約は固定費一覧で **参照のみ**。編集/削除/並べ替えのUIを契約行に付けない。
4. 個人/共有は `Contract.scope`（未設定=共有）で判定。設定ON時のみ **自分(owner===uid)の個人契約**を追加。**他人の個人契約は表示しない**。
5. 既存データ互換：`scope` 未設定の契約は共有扱い。`renewalDate` 任意のまま。
6. カレンダー/日別モーダル/リストは **正規化型 `FixedItem`** に統一して描画する（固定費・契約を同じ型に変換してから渡す）。`source` で編集可否を分岐。
7. 設定トグルは **localStorage**（`showPersonalInFixedCosts`）。Firestore/Rules 変更なし。
8. 品質ゲート厳守：`npm run lint`（警告0）／`npx tsc -b`（型0）／`npm test`（全pass）。

## 3. 正規化ユーティリティ（`src/utils/fixedItem.ts`・全文）

```typescript
import type { Contract, FixedCost, FixedCostFrequency, ContractType, ContractScope } from '../types'

// 固定費一覧（カレンダー/リスト）で固定費と契約を同列に扱うための正規化型。
export interface FixedItem {
  id: string
  source: 'fixedCost' | 'contract'
  name: string
  amount: number
  isVariable: boolean
  dayOfMonth: number
  frequency: FixedCostFrequency  // contract は monthly|yearly のみ
  month?: number                 // yearly のとき発生月
  baseYear?: number              // fixedCost の every2/3years 用
  scope: ContractScope           // fixedCost は常に 'shared'
  contractType?: ContractType    // contract のときのみ
  paymentMethod?: string
  memo?: string
  order: number
}

export function fixedCostToItem(c: FixedCost): FixedItem {
  return {
    id: c.id,
    source: 'fixedCost',
    name: c.name,
    amount: c.amount,
    isVariable: !!c.isVariable,
    dayOfMonth: c.dayOfMonth,
    frequency: c.frequency ?? 'monthly',
    month: c.month,
    baseYear: c.baseYear,
    scope: 'shared',
    paymentMethod: c.paymentMethod,
    memo: c.memo,
    order: c.order,
  }
}

// 契約 → FixedItem。renewalDate 未設定なら null（一覧に出さない）。
export function contractToItem(c: Contract): FixedItem | null {
  if (!c.renewalDate) return null
  const [y, m, d] = c.renewalDate.split('-').map(Number)
  if (!y || !m || !d) return null
  return {
    id: c.id,
    source: 'contract',
    name: c.name,
    amount: c.amount,
    isVariable: false,
    dayOfMonth: d,
    frequency: c.frequency, // 'monthly' | 'yearly'
    month: c.frequency === 'yearly' ? m : undefined,
    scope: c.scope ?? 'shared',
    contractType: c.contractType,
    paymentMethod: c.paymentMethod,
    memo: c.memo,
    order: c.order,
  }
}

// 固定費一覧に表示する FixedItem を組み立てる。
// - 固定費：全件
// - 契約：共有（＋ includePersonal かつ owner===currentUid の個人）かつ renewalDate あり
export function buildFixedItems(
  fixedCosts: FixedCost[],
  contracts: Contract[],
  opts: { includePersonal: boolean; currentUid: string | null },
): FixedItem[] {
  const items: FixedItem[] = fixedCosts.map(fixedCostToItem)
  for (const c of contracts) {
    const scope = c.scope ?? 'shared'
    if (scope === 'personal') {
      if (!opts.includePersonal) continue
      if (!opts.currentUid || c.owner !== opts.currentUid) continue
    }
    const item = contractToItem(c)
    if (item) items.push(item)
  }
  return items
}
```

> `isApplicableThisMonth` / `getEffectiveDay`（`utils/fixedCost.ts`）は `FixedItem` でもそのまま使える（`frequency`/`month`/`baseYear`/`dayOfMonth` を参照する純関数のため）。引数型を `FixedCost` から「必要フィールドを持つ最小型」に緩めるか、`FixedItem` を受けられるようにオーバーロード/型調整する。**最小修正**として、これらの関数のシグネチャを `Pick<FixedItem, 'frequency'|'month'|'baseYear'|'dayOfMonth'>` 互換に変更するのが安全（既存呼び出しは FixedCost を渡しているため互換）。

## 5. FixedCostsPage 改修（`src/pages/FixedCostsPage.tsx`）

### 5.1 データ取得
- 既存：`fetchFixedCosts` で固定費。
- 追加：契約も取得。`useContracts()` を利用（共有/個人とも同コレクション）。
- 現在ユーザー uid：`useHousehold()` の `user?.uid`（`useHousehold` は user を持つ）。
- 個人表示フラグ：`getShowPersonalInFixedCosts()`（state で保持、設定変更に追従させたい場合は `storage` イベント or 画面マウント時読み取りでよい。MVP はマウント時読み取り）。

```typescript
const { user } = useHousehold()
const { contracts } = useContracts()
const [showPersonal] = useState(getShowPersonalInFixedCosts())

const items = useMemo(
  () => buildFixedItems(costs, contracts, { includePersonal: showPersonal, currentUid: user?.uid ?? null }),
  [costs, contracts, showPersonal, user?.uid],
)
```

### 5.2 カレンダー集約（FixedItem ベースに変更）
```typescript
const costsByDay = new Map<number, FixedItem[]>()
for (const item of items) {
  if (!isApplicableThisMonth(item, viewYear, viewMonth)) continue
  const { effectiveDay, overflows } = getEffectiveDay(item.dayOfMonth, viewYear, viewMonth)
  if (!overflows) {
    const arr = costsByDay.get(effectiveDay) ?? []
    arr.push(item)
    costsByDay.set(effectiveDay, arr)
  }
}
```

### 5.3 月次合計（契約を加算）
```typescript
const applicable = items.filter(it => {
  const freq = it.frequency
  if (freq === 'monthly') return it.dayOfMonth <= daysInMonth
  return isApplicableThisMonth(it, viewYear, viewMonth)
})
const monthlyTotal = applicable.filter(it => !it.isVariable).reduce((s, it) => s + it.amount, 0)
const variableCount = applicable.filter(it => it.isVariable).length  // 実質 fixedCost のみ
```

### 5.4 リスト表示（デスクトップ右カラム）
- 固定費（`source==='fixedCost'`）：従来の `SortableFixedCostRow`（編集・削除・D&D）。D&D 対象は固定費のみ（contract を SortableContext に入れない）。
- 契約（`source==='contract'`）：**参照専用行**を別セクション（見出し「契約（参照）」）で表示。ハンドル/編集/削除ボタンなし。種別バッジ＋個人バッジを表示。
- 並べ替え（reorder）対象は固定費のみ。`handleDragEnd` は `costs`（FixedCost）に対してのみ動作（現状のまま）。

> 実装方針：右カラムを「固定費セクション（編集可）」＋「契約セクション（参照）」の2ブロックに分割。カレンダー（左）は混在表示。

### 5.5 編集/削除導線
- 契約行・契約のカレンダー項目・日別モーダルの契約項目は **onEdit を呼ばない**（または各管理ページへ `navigate('/subscriptions')` / `/contracts`）。MVP は**無反応（参照のみ）**でよい。

## 7. フォームへの個人/共有セレクタ追加

### 7.1 SubscriptionsPage（`src/pages/SubscriptionsPage.tsx`）
- `FormState` に `scope: ContractScope` を追加（既定 `'shared'`）。
- `contractToForm` で `c.scope ?? 'shared'` を反映。
- フォームに2択トグル（共有/個人）を追加（「自動更新あり」付近）。
- `handleSubmit` の `data` に：
  ```typescript
  data.scope = form.scope
  if (form.scope === 'personal' && user?.uid) data.owner = user.uid
  // 共有に切替時は owner を消す（更新時）。Firestore は undefined を書けないため
  // 既存 owner を消すには deleteField 相当が必要 → 詳細は 7.3 参照
  ```
- `user` は `useHousehold()` から取得（このページは未使用なら import 追加）。

### 7.2 ContractsPage（`src/pages/ContractsPage.tsx`）
- 同様に `scope` をフォーム・保存に追加。種別（insurance/loan/other）はそのまま。

### 7.3 owner のクリア（共有へ戻す場合）
- `personal→shared` に変更した契約の `owner` を残さないため、更新時に `owner` をクリアしたい。
- 既存 `updateContract`（`createHouseholdCrud` の update）が `updateDoc` の場合、`owner: deleteField()` を渡す必要がある。**最小対応**：`scope==='shared'` のときは `owner` を空文字でなく**未設定のまま**にしたいが、表示判定は `scope` のみで行うため **owner が残っていても害はない**（personal 判定は scope 優先）。よって MVP では **owner のクリアは不要**（scope を見て判定）。

> 重要：表示・集約の判定は必ず `scope` を主、`owner` は personal のときの所有者照合のみに使う。これにより owner クリア不要。
