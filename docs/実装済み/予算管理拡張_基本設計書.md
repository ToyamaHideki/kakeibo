## 1. 目的

予算管理画面の運用負荷と視認性を改善する。具体的には以下 3 機能を Ver 1.0200 として一括投入する。

| # | 機能 | 解決する課題 |
|---|---|---|
| 1 | 前月予算の引き継ぎ | 毎月の予算入力の手作業を削減 |
| 2 | 設定済み／未設定のグルーピング表示 | 実際に使うカテゴリが埋もれて見つけにくい |
| 3 | 予算画面からカテゴリ並べ替え | 優先度順を自分で調整できない |

---

## 2. スコープ

| # | 機能 | UI 配置 |
|---|---|---|
| 1 | 「前月の予算を引き継ぐ」ボタン | 予算画面上部（月ナビゲーション下） |
| 2 | グループヘッダー「予算設定済み」「予算未設定」 | カテゴリリスト内に区切りとして挿入 |
| 3 | 「並べ替え」モード切替ボタン＋ DnD ハンドル | 予算画面上部＋並べ替えモード時の各カード |

非対象：
- 収入カテゴリの予算（既存通り対象外）
- 月別収支画面側の特別対応（カテゴリ自体の `order` を更新するため、カテゴリ別モードの並びは結果として変化するが、これは想定挙動）

## 4. データフロー

### 4.1 前月予算引き継ぎ

```
[前月の予算を引き継ぐ] 押下
   │
   ├─ adjacentMonth(yearMonth, -1) で前月の yearMonth を計算
   │
   ├─ fetchBudget(householdId, prevYM)  ← 既存
   │      └→ Record<string, number>
   │
   ├─ fetchBudget(householdId, currentYM) ← 既存（再フェッチ）
   │      └→ 現在の budgets
   │
   ├─ 補完対象を抽出：
   │      prev[id] > 0 && (current[id] === undefined || current[id] === 0)
   │      → そのキー群を copyMap として組み立て
   │
   ├─ copyMap が空 → トースト「引き継ぐ予算がありません」
   │
   └─ copyMap を setDoc(merge:true) で書き込み → reload → トースト「N 件補完しました」
```

### 4.2 グルーピング表示

```
useBudget(yearMonth) → budgets
useCategories() → categories (expense のみ抽出 + order 昇順)

  ┌──────────────────────────────┐
  │ assignedCats = expenseCats   │
  │   .filter(c => budgets[c.id] > 0) │
  ├──────────────────────────────┤
  │ unassignedCats = expenseCats │
  │   .filter(c => !(budgets[c.id] > 0)) │
  └──────────────────────────────┘
       ↓
  グループヘッダー + グリッド を 2 連
```

### 4.3 並べ替え

```
[並べ替え] 押下 → isReordering = true
   │
   ├─ 1 列縦並びレイアウト
   ├─ 各カードに drag handle
   ├─ 予算入力 disabled
   │
   ユーザーがドラッグ
   │
   ├─ onDragEnd（SortableContext ごと）
   │     └→ そのグループ内で arrayMove
   │
   ├─ 「保存」処理：
   │     - 設定済みグループの items[i].order = i * 1000
   │     - 未設定グループの items[i].order = (assignedCount + i) * 1000
   │     - 各カテゴリで updateCategory(id, { order })  ← 既存
   │     - reload (categories)
   │
   [完了] 押下 → isReordering = false（通常モードに戻る）
```

## 6. 表示条件・分岐

| 状況 | 振る舞い |
|---|---|
| 前月予算がすべて 0 か空 | ボタン押下時にトースト「引き継ぐ予算がありません」 |
| 当月予算がすべて設定済み | 補完対象が 0 件 → 同上トースト |
| 設定済みグループが 0 件 | グループ見出しは非表示、グリッドも描画しない |
| 未設定グループが 0 件 | 同上 |
| 並べ替えモード時に月ナビゲーション | ボタン表示は維持（無効化はしない、押下時は通常モードに戻す挙動でなく単に画面遷移） |
| ゲストモード | 既存 guestStore 経由で動作（fetchBudget / updateBudgetAmount 同様、新規 helper も対応） |

## 7. 非機能要件

### 7.1 パフォーマンス
- 引き継ぎ：fetchBudget x2 + setDoc x1（O(N) で N=カテゴリ数）
- 並べ替え保存：updateCategory を `Promise.all` で並列
- グルーピング：useMemo で budgets / categories の変化時のみ再計算

### 7.2 永続化
- 引き継ぎ後の予算値：Firestore に即時保存
- 並べ替え後の order：完了時 or DnD 完了時に Firestore 書き込み

### 7.3 アクセシビリティ
- ハンドル：`aria-label="並び替え"`
- グループヘッダー：`<h2>` で構造化
- 並べ替えボタン：トグル状態を `aria-pressed` で明示

### 7.4 デザイン一貫性
- ボタンは既存スタイル（sage 系）踏襲
- グループヘッダーは `text-xs font-semibold text-gray-500 uppercase tracking-wide` 系（設定画面のセクションヘッダーと統一感）
- ハンドルは ShoppingListPage と同じ `GripIcon`

## 8. 既知リスク・考慮事項

| リスク | 対応 |
|---|---|
| 並べ替えで他画面のカテゴリ表示順が変わる | 仕様通り。ユーザーが意識して並べ替えする想定 |
| 引き継ぎ後にユーザーが「やっぱり戻したい」 | 元の状態は記録しない（複雑化）。トースト確認で済ませる |
| 引き継ぎ実行中の連打 | ボタンを `disabled` でガード（loading state） |
| 並べ替え中に予算を編集される | 並べ替えモードでは input を disabled にして両立を回避 |
| ゲストモードでの並べ替え | `updateCategory` は guest 対応済み → そのまま動作 |
| グループまたぎドラッグの誤動作 | SortableContext を 2 つに分けて構造的に禁止 |
| 設定済み→未設定（予算 0 にした）瞬間のレイアウト変化 | reload で自然に再描画。order は変更しないため次回並べ替えで調整可能 |
