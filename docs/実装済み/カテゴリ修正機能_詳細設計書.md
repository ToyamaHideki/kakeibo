## ⚠ 実装担当者への注意（必読）

1. **既存挙動を壊さない**：CategoryAddModal は新規追加・削除のみで日常運用されている。型 props を追加するときは **optional（`?:`）** で追加し、未指定でも動作するようにする。
2. **新規 Firestore 関数は不要**。`updateCategory`（`src/firebase/firestore.ts:37`）と `updatePersonalCategory`（`src/firebase/personalFirestore.ts:26`）が既に存在し、Partial を受ける。両方ともゲスト対応済み。
3. **typeは編集不可**。Props の `type` で渡される値（収入 or 支出）が編集モードのカテゴリにも一致する前提。受け取ったカテゴリの type が違う場合は editingId をセットしない（防御）。
4. **編集中行の判定**：`editingId === cat.id` で行のスタイルを切替。アクセントバー or 背景色のいずれかで実装。
5. **編集対象を削除した時の防御**：`handleDelete(cat)` 内で `editingId === cat.id` なら削除成功後 `cancelEdit()` を呼ぶ。
6. **モーダルを閉じた時のクリーンアップ**：`handleClose()` 内で `setEditingId(null)` も含める。
7. **lint 警告 0 / tsc 型 0 / vitest 全 pass 厳守**。
8. **デプロイは hosting のみ**。Firestore Rules 変更なし。

```typescript
async function handleDelete(cat: Category) {
  if (!await confirm(`「${cat.name}」を削除しますか？\nこのカテゴリで登録済みの取引は残りますが、カテゴリとの紐付けが失われます。`)) return
  await (deleteCategoryFn ?? ((id: string) => deleteCategory(householdId!, id)))(cat.id)
  onDeleted(cat.id)
  if (editingId === cat.id) cancelEdit()  // 追加：編集対象削除時の自動解除
}
```

#### handleSubmit の修正

```typescript
async function handleSubmit(e: FormEvent) {
  e.preventDefault()
  if (!name.trim()) return
  setSaving(true)
  try {
    if (isEditing && editingId) {
      // 編集モード
      const patch: Partial<Omit<Category, 'id'>> = {
        name: name.trim(),
        color,
        ...(type === 'expense' ? { expenseType } : {}),
      }
      await (updateCategoryFn ?? ((id: string, data: Partial<Omit<Category, 'id'>>) => updateCategory(householdId!, id, data)))(editingId, patch)
      const original = categories.find(c => c.id === editingId)
      if (original) onUpdated({ ...original, ...patch })
      cancelEdit()
    } else {
      // 既存の新規追加処理（変更なし）
      const newCat = {
        name: name.trim(),
        type,
        color,
        order: nextOrder,
        ...(type === 'expense' ? { expenseType } : {}),
      }
      const id = await (addCategoryFn ?? ((cat: Omit<Category, 'id'>) => addCategory(householdId!, cat)))(newCat)
      onAdded({ ...newCat, id })
      setName('')
      setColor(PRESET_COLORS[0]!)
      setExpenseType('variable')
    }
  } finally {
    setSaving(false)
  }
}
```

### 12.3 `updateCategoryFn` の Props 型衝突回避

`updateCategory`（既存 firestore import）と関数引数名 `updateCategoryFn` を混同しないよう、CategoryAddModal 内では `updateCategory` を fallback として使う際に `?? ((id, data) => updateCategory(householdId!, id, data))` の形を取る（addCategory と同じパターン）。

### 12.4 PersonalPage が個人カテゴリしか持たない場合の `updateCategoryFn` 設計

PersonalPage は `updateCategoryFn={(id, data) => updatePersonalCategory(user.uid, id, data)}` で渡す。これにより CategoryAddModal が個人 Firestore に書き込む。`onCategoryUpdated` は `usePersonalCategories` の `updateCategoryLocally` を渡す。
