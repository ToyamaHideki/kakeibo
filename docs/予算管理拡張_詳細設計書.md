## ⚠ 実装担当者への注意（必読）

1. **既存挙動を壊さない**：BudgetPage は既存ユーザーが日常的に使う画面。「予算入力 → blur で自動保存」「月切替」「合計サマリー」「進捗バー色分け」等の既存機能を一切壊さないこと。テスト（`src/test/BudgetPage.test.tsx`）は全て pass する形で改修すること。
2. **DnD の見本は `src/pages/ShoppingListPage.tsx`** を踏襲する（@dnd-kit/core + sortable、`verticalListSortingStrategy`、`closestCenter`、`arrayMove`）。
3. **`updateCategory`（`src/firebase/firestore.ts:37`）はゲスト対応済み**。並べ替えはこの既存関数で各カテゴリの `order` を更新する。
4. **新規 helper `copyBudgetFromPrevious`** はゲスト対応必須。`fetchBudget` / `setDoc` のゲスト分岐パターンを踏襲する（同ファイル内 `GUEST_HOUSEHOLD_ID` 判定）。
5. **0 円予算は「未設定」と同等**として扱う（補完対象、未設定グループ）。型上は `Record<string, number>` のままで OK。
6. **グループまたぎ DnD は禁止**：SortableContext を 2 つに分割して構造的に防ぐ。1 つの DndContext 内で onDragEnd 分岐より安全。
7. **並べ替え完了時の保存**：assigned グループの items[i].order = i * 1000、unassigned グループの items[i].order = (assignedCount + i) * 1000 で連番採番。これで「設定済みが必ず上、未設定が下」を order 値だけで実現できる。
8. **lint 警告 0 / tsc 型 0 / vitest 全 pass を厳守**。
9. **デプロイは hosting のみ**。Firestore Rules 変更なし。

## 2. Firestore helper の追加

### `src/firebase/firestore.ts` Budget セクション末尾に追加

```typescript
import type { BudgetMap } from '../types'

/**
 * 前月の予算を当月へ「空欄補完」で引き継ぐ。
 * - prev[id] > 0 かつ current[id] が 0/undefined のキーだけコピー
 * - 戻り値：補完件数
 */
export async function copyBudgetFromPrevious(
  householdId: string,
  currentYearMonth: string,
  previousYearMonth: string,
): Promise<number> {
  const [prev, current] = await Promise.all([
    fetchBudget(householdId, previousYearMonth),
    fetchBudget(householdId, currentYearMonth),
  ])

  const patch: BudgetMap = {}
  for (const [categoryId, amount] of Object.entries(prev)) {
    if (amount > 0 && !(current[categoryId] > 0)) {
      patch[categoryId] = amount
    }
  }
  const count = Object.keys(patch).length
  if (count === 0) return 0

  if (householdId === GUEST_HOUSEHOLD_ID) {
    for (const [cid, amount] of Object.entries(patch)) {
      guestUpdateBudget(currentYearMonth, cid, amount)
    }
  } else {
    await setDoc(
      doc(db, 'households', householdId, 'budgets', currentYearMonth),
      patch,
      { merge: true },
    )
  }
  return count
}
```

**注意**：
- `fetchBudget` / `guestUpdateBudget` / `GUEST_HOUSEHOLD_ID` は既に同ファイル内 import 済み。新規 import は `BudgetMap` のみ。
- 既存の `current[categoryId] > 0` は `undefined > 0 === false` で安全に判定。

## 3. useBudget の調整（任意）

`src/hooks/useBudget.ts` に **reload 関数を露出**（引き継ぎボタン押下後の再フェッチ用）。

```typescript
import { useCallback, useEffect, useState } from 'react'
import { fetchBudget, updateBudgetAmount } from '../firebase/firestore'
import { useHousehold } from './useHousehold'
import type { BudgetMap } from '../types'

export function useBudget(yearMonth: string) {
  const { householdId } = useHousehold()
  const [budgets, setBudgets] = useState<BudgetMap>({})
  const [loading, setLoading] = useState(true)

  const reload = useCallback(async () => {
    if (!householdId) return
    setLoading(true)
    try {
      const data = await fetchBudget(householdId, yearMonth)
      setBudgets(data)
    } finally {
      setLoading(false)
    }
  }, [householdId, yearMonth])

  useEffect(() => {
    void reload()
  }, [reload])

  async function saveBudgetAmount(categoryId: string, amount: number) {
    if (!householdId) return
    await updateBudgetAmount(householdId, yearMonth, categoryId, amount)
    setBudgets(prev => ({ ...prev, [categoryId]: amount }))
  }

  return { budgets, loading, saveBudgetAmount, reload }
}
```

async function handleCopyFromPrevious() {
  if (!householdId || copying) return
  setCopying(true)
  try {
    const prevYM = adjacentMonth(yearMonth, -1)

#### 並べ替えハンドラ

```typescript
const handleDragEnd = useCallback(async (event: DragEndEvent, group: 'assigned' | 'unassigned') => {
  const { active, over } = event
  if (!over || active.id === over.id || !householdId) return

  const list = group === 'assigned' ? assignedCats : unassignedCats
  const oldIndex = list.findIndex(c => c.id === active.id)
  const newIndex = list.findIndex(c => c.id === over.id)
  if (oldIndex === -1 || newIndex === -1) return

  const reordered = arrayMove(list, oldIndex, newIndex)
  const newAssigned = group === 'assigned' ? reordered : assignedCats
  const newUnassigned = group === 'unassigned' ? reordered : unassignedCats

  // 連番採番：assigned は 0..n-1、unassigned は n..n+m-1
  const updates: Promise<void>[] = []
  newAssigned.forEach((c, i) => {
    const next = i * 1000
    if (c.order !== next) updates.push(updateCategory(householdId, c.id, { order: next }))
  })
  newUnassigned.forEach((c, i) => {
    const next = (newAssigned.length + i) * 1000
    if (c.order !== next) updates.push(updateCategory(householdId, c.id, { order: next }))
  })

  await Promise.all(updates)
  await reloadCategories()
}, [householdId, assignedCats, unassignedCats, reloadCategories])
```

  if (isReordering) {

function SortableBudgetCard({ cat, ...rest }: { cat: Category } & BudgetCardProps) {
  const { attributes, listeners, setNodeRef, transform, transition, isDragging } =
    useSortable({ id: cat.id })
  const style = {
    transform: CSS.Transform.toString(transform),
    transition,
    opacity: isDragging ? 0.4 : 1,
  }
  return (
    <div ref={setNodeRef} style={style} className="flex items-center gap-2 bg-white rounded-xl shadow-sm border border-gray-100 px-3 py-2">
      <button
        {...attributes}
        {...listeners}

        tabIndex={-1}
        aria-label="並び替え"
      >
        <GripIcon />
      </button>
      <BudgetCardInner cat={cat} disabled {...rest} />
    </div>
  )
}

## 9. 補足

### 9.1 既存呼び出し箇所の grep（実装前確認）

```
grep -rn "useBudget" src/
grep -rn "useCategories" src/
grep -rn "updateBudgetAmount" src/
```

`useBudget()` の戻り値 destructure 箇所が増える（`reload` 追加）ため、他で `useBudget` を使っている箇所があれば破壊しないか確認。grep 結果が `BudgetPage.tsx` のみなら影響なし。

### 9.2 useCategories の reload 露出パターン

既存の useCategories が初回 fetch のみで reload を持たない場合、useBudget の reload パターン（useCallback で wrap → useEffect で初回呼び出し → 戻り値に含める）を踏襲して追加。

### 9.3 トースト UI のスタイル

シンプルに `fixed bottom-20 md:bottom-6` で配置。z-index は FAB（z-20）より上の z-30。既存トーストパターンが他にあれば（confirm 系コンポーネント等）、そちらに揃えても可。

### 9.4 並べ替え時の合計サマリー

並べ替えモード時は合計サマリーを非表示にすると画面密度が下がって操作しやすい。本設計書ではそのように記述している。表示維持したい場合は条件を外す。
